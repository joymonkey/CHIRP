# CHIRP System Audio Generation & Pipeline

This directory contains the audio assets, conversion scripts, and documentation for CHIRP Audio Trigger's system voice prompts.

The system audio files are embedded directly into firmware flash memory (`PROGMEM`) as hex byte arrays in [`src/system_audio_data.cpp`](../src/system_audio_data.cpp) and declared in [`src/system_audio_data.h`](../src/system_audio_data.h).

---

## Directory Structure

```text
Sounds/
├── 0_system_wav/           # Master WAV files
│   ├── 0000.wav
│   ├── battery.wav
│   └── ...
├── 0_system_mp3/           # Trimmed, 16 kbps mono MP3s (generated by script)
│   ├── 0000.mp3
│   ├── battery.mp3
│   └── ...
├── convert_system_audio.py # Python script: trims silence, encodes MP3s, generates C++ code
└── README.md               # This documentation
```

## Audio Specifications

To minimize flash consumption on the microcontroller while maintaining vocal intelligibility:

- **Format:** MP3
- **Channels:** 1 (Mono)
- **Sample Rate:** 22,050 Hz (22.05 kHz)
- **Bitrate:** 16 kbps Constant Bitrate (CBR)
- **Silence Trimming:** Automated start/end threshold cutoff at -45 dB (strips dead air before and after vocal line for immediate playback response and flash savings)

## Voice Generation Workflow

The distinct personality for the CHIRP voice prompt combines GLaDOS (Portal) inflection with KX Security Droid (Star Wars / *Jedi: Survivor*, K-2SO style) resonance.

### Step 1: Base Vocal Generation (GLaDOS TTS)
1. Generate base vocal line using a **GLaDOS Text-to-Speech** generator ( https://github.com/nimaid/GLaDOS-TTS ).
2. *Tip:* Use punctuation (periods, commas, dashes) and phonetic spelling when necessary to enforce robotic cadence and correct pronunciation of technical jargon or acronyms (e.g., "C-H-I-R-P").
3. Export the raw vocal file as an uncompressed `.wav`.

### Step 2: Voice Conversion (Applio / RVC)
1. Load the generated WAV into **Applio** (Retrieval-based Voice Conversion).
2. **Model:** `KXSecurityDroid` (trained on KX security droid dialogue from *Star Wars Jedi: Survivor*).
3. **Recommended Conversion Settings:**
   - **Pitch Shift (Key):** `0` (adjust ± semitones if the input GLaDOS pitch is too high or low)
   - **Index Rate:** `0.75 - 0.85` (balance between GLaDOS cadence and KX droid vocal timbre)
   - **Filter Radius:** `3`
   - **Protect Voiceless Consonants:** `0.33`
4. Export the converted vocal as `.wav` (Applio typically names this `<name>_output.wav`).

### Step 3: Add to System Sounds
1. Rename the file to remove `_output` and follow the lowercase naming standard (e.g. `battery.wav`, `mass_storage.wav`, `padawan.wav`).
   - The base name (without extension) is what the firmware uses for audio lookup (e.g., `"battery"` matches `battery.mp3`).
2. Drop the `.wav` file into [`Sounds/0_system_wav/`](0_system_wav/).

## Embedding Audio into Firmware

Run the conversion script from the repository root:

```powershell
python Sounds/convert_system_audio.py
```

### What the Script Does:
1. **Detects changes:** Checks all files in `Sounds/0_system_wav/`. Any new or modified WAV file is automatically processed.
2. **Trims dead air:** Applies an automated 2-pass silence filter (`-45 dB` threshold) via FFmpeg to remove dead silence from the start and end of the clip, eliminating trigger delay.
3. **Downsamples & Encodes:** Converts each clip to 16 kbps CBR mono at 22,050 Hz into `Sounds/0_system_mp3/`.
4. **Generates C++ code:** Converts all MP3s into `PROGMEM` hex arrays and updates:
   - [`src/system_audio_data.h`](../src/system_audio_data.h)
   - [`src/system_audio_data.cpp`](../src/system_audio_data.cpp)

> **Tip:** Pass `--force` to re-encode all files from scratch:
> ```powershell
> python Sounds/convert_system_audio.py --force
> ```
